# Maintainer Workflow

This document records the internal build pipeline, dictionary compilation, and upstream maintenance procedures for yomigana. These instructions are intended for library maintainers. Users integrating yomigana do not need these tools or knowledge.

---

## 1. Quick Reference

```sh
npm ci                         # Install dev dependencies
npm test                       # Run regression test suite
npm run build                  # Rebuild both Kuromoji and offline runtime bundles
npm run dev                    # Start local static server (http://127.0.0.1:4173/)
npm run setup -- --alignment   # Recompile dictionaries from upstream release archives
```

---

## 2. Directory Architecture

| Directory | Role | Notes |
| --- | --- | --- |
| `src/` | Primary library source & CSS | Edit here. Uses ES modules and Web Workers. |
| `presets/global-overrides.js` | Prepared optional global entries | Exported as `globalOverrides`; both full demos enable it. |
| `dist/offline/` | Standalone offline distribution | Generated by `build-offline.mjs`. Do not edit manually. |
| `vendor/suzume/` | Suzume runtime & WASM | Copied from `@libraz/suzume` during setup. |
| `vendor/kuromoji/` | Kuromoji bundle & IPADIC | Generated by `build-kuromoji.mjs`. Contains 12 `.dat.gz` files. |
| `vendor/readings/` | Compiled JMdict data & manifest | Generated by `setup.mjs`. Content-hashed JSON + gzip. |
| `scripts/` | Build scripts & maintainer tooling | `setup.mjs`, `build-kuromoji.mjs`, `build-offline.mjs`, `serve-demos.mjs`. |
| `tests/` | Automated test suite | Node.js native test runner (`node --test tests/*.test.mjs`). |
| `site/`, `index.html` | Project homepage & playground | Uses local assets and module workers. |
| `yomu/` | Yomu PWA reader application | Production reader app with voice playback and offline support. |
| `demo-*/` | Targeted showcase examples | `demo-basic`, `demo-online`, and `demo-offline`. |

## 3. Dictionary Setup & Compilation (`scripts/setup.mjs`)

yomigana does not ship raw uncompiled dictionary databases. Instead, `scripts/setup.mjs` fetches pinned upstream archives into `.dictionary-cache/` (cache directory ignored by git), filters the data using `scripts/dictionary-build.mjs`, and outputs optimized, content-hashed JSON files into `vendor/readings/`.

### Commands

```sh
# Standard build: common vocabulary + attested compounds + per-kanji alignments
npm run setup -- --alignment

# Full dictionary: all JMdict entries without common-word filtering
npm run setup -- --full --alignment
```

### Upstream Sources

- **JMdict (via jmdict-simplified)**:
  - Source: [`scriptin/jmdict-simplified`](https://github.com/scriptin/jmdict-simplified)
  - Pinned version variable: `version` in `scripts/setup.mjs` (e.g. `3.6.2+20260928191014`).
  - Filtering logic: `scripts/dictionary-build.mjs` removes English definitions, retains attested all-kanji compounds (4–16 characters) composed of common components, preserves uncommon alternative readings for selected spellings, and records sense-local preference indicators.
- **JmdictFurigana**:
  - Source: [`Doublevil/JmdictFurigana`](https://github.com/Doublevil/JmdictFurigana)
  - Pinned version variable: `alignmentVersion` in `scripts/setup.mjs` (e.g. `2.3.1+2026-09-25`).
  - Enabled via `--alignment` flag. Outputs `alignment-<hash>.json` and updates `manifest.json`.
- **Suzume**:
  - Copies `@libraz/suzume/dist/` into `vendor/suzume/` and downloads its upstream license.

### Output Files in `vendor/readings/`

- `manifest.json`: Records current versions, word count, license attribution, and content hashes.
- `readings-<hash>.json` and `.gz`: Compiled JMdict dictionary mappings.
- `alignment-<hash>.json` and `.gz`: Per-kanji furigana mappings.
- `NOTICE.txt`: Legal attribution and licensing notices (CC BY-SA 4.0).

## 4. Building Kuromoji (`scripts/build-kuromoji.mjs`)

Kuromoji's IPADIC dictionary (~17 MB compressed, 12 `.dat.gz` files) is pinned via npm and bundled into browser-friendly ES module format:

```sh
npm run build:kuromoji
```

What this does:
1. Bundles Kuromoji's `Tokenizer.js` and `DynamicDictionaries.js` with `esbuild` into `vendor/kuromoji/runtime.js`.
2. Copies the 12 `.dat.gz` dictionary files from `node_modules/kuromoji/dict/` into `vendor/kuromoji/dict/`.
3. Copies `LICENSE-2.0.txt`, `NOTICE.md`, and doublearray dependencies license.
4. Generates `vendor/kuromoji/build-info.json` recording upstream package version, byte sizes, and SHA-256 digests for each dictionary file.

### Updating Kuromoji Upstream

To update Kuromoji to a newer upstream npm release:

```sh
npm install --save-dev --save-exact kuromoji@<NEW_VERSION>
npm run build
npm test
```

Check the SHA-256 digests recorded in `vendor/kuromoji/build-info.json`. Commit the lockfile, updated `vendor/kuromoji/` files, and rebuilt `dist/offline/` assets together.

## 5. Building the Offline Distribution (`scripts/build-offline.mjs`)

The offline build packages yomigana into self-contained scripts that run without network access or HTTP servers (including double-clicking `file://` HTML files):

```sh
npm run build:offline
```

What this produces in `dist/offline/`:
- `runtime.js`: IIFE-wrapped yomigana runtime exposing `globalThis.yomiganaWeb` (replaces worker provider with `src/offline-provider.js`).
- `suzume-wasm.js`: Suzume WASM binary encoded as a base64 `data:application/wasm` URI.
- `readings.js`: JMdict readings wrapped into `globalThis.yomiganaOfflineAssets.readings`.
- `alignments.js`: JmdictFurigana mappings wrapped into `globalThis.yomiganaOfflineAssets.alignments`.
- `kuromoji-dict.js`: 12 IPADIC `.dat.gz` dictionaries encoded as base64 strings (decompressed at runtime via browser `DecompressionStream`).
- `build-info.json`: Build provenance, dictionary hashes, and version stamps.
- Upstream license and notice files (`NOTICE.txt`, `SUZUME-LICENSE.txt`, `KUROMOJI-LICENSE.txt`).

*Note: `npm run build` runs both `build:kuromoji` and `build:offline` in sequence.*

## 6. Local Preview Server (`scripts/serve-demos.mjs`)

```sh
npm run dev
```

Runs a lightweight Node.js HTTP server at `http://127.0.0.1:4173/`:
- Serves the homepage (`index.html`), `yomu/`, and all three demos (`demo-basic/`, `demo-online/`, `demo-offline/`).
- Handles Gzip compression on-the-fly (`Accept-Encoding: gzip`).
- Serves immutable cache headers (`max-age=31536000, immutable`) for content-hashed `-<hash>.json` files.
- Sets correct MIME types, including `application/wasm` for WebAssembly.

## 7. Quality & Regression Checklist

Before committing changes or cutting a release:

1. **Run tests**: `npm test` (verify all unit tests, integration tests, and accessibility checks pass).
2. **Rebuild offline assets**: `npm run build:offline` whenever `src/` or `presets/` changes to ensure `dist/offline/runtime.js` remains in sync. Rebuild Kuromoji assets as well only when its runtime or dictionary changes. App-owned lists such as `yomu/yomigana-overrides.js` are separate scripts, so edits there do not require rebuilding the library bundle; update the Yomu service-worker cache version when publishing changed app assets.
3. **Accessibility**: Verify all ruby annotations keep `aria-hidden="true"` and `data-nosnippet` on `<rt>` and child `<span>` elements.
4. **Licenses**: Ensure any updated dictionary or package preserves third-party notices in `vendor/` and `dist/offline/`.
